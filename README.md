# File List Studio

File List Studio is a native Tauri 2 desktop application for creating structured catalogs of local files and folders. The frontend uses Vue 3 and TypeScript; filesystem scanning, metadata extraction, thumbnails, hashing, project persistence, and CSV/XLSX export are implemented through Rust commands.

## Run in development

Install Node.js, pnpm, Rust, and the Tauri prerequisites for your operating system. Then run:

```bash
pnpm install
pnpm tauri dev
```

For image dimensions, EXIF, audio/video duration, resolution, bitrate, sample rate, channels, album, and artist metadata, the application uses `ffprobe` when available. On Windows development machines, install FFmpeg and ensure `ffprobe.exe` is on PATH. The GitHub Actions workflow installs FFmpeg automatically for the build environment.

## Main features

The application scans selected files and folders, optionally includes subfolders, and supports comma-separated excluded folder names and extensions. It reports exact progress, continues past individual read errors, and can cancel active scans or hash jobs. Results include filesystem dates, type, size, path, EXIF fields, image dimensions and thumbnails, media duration and technical properties, and audio tags when the source exposes them.

The result table supports search, type filtering, sorting, column visibility, inline editing of name/comments/tags/title, and MD5/SHA-256 calculation on demand. Projects can be saved to and reopened from `.flsp` files. Rust writes the current filtered view directly to UTF-8 CSV with a BOM for reliable Arabic/Excel handling, or to a native XLSX workbook. The interface includes Arabic and English modes through the language toggle.

## Build a distributable application

```bash
pnpm install
pnpm tauri build
```

## Build Windows through GitHub Actions

The workflow at `.github/workflows/build-windows.yml` runs on `windows-latest`. It installs pnpm, Node.js, FFmpeg/ffprobe, and Rust, then produces NSIS (`.exe`) and MSI (`.msi`) installers. It uploads both installers as an artifact. Run it from **Actions → Build Windows Desktop App → Run workflow**, or push a tag such as:

```bash
git tag v0.2.0
git push origin v0.2.0
```

Tags beginning with `v` also create a GitHub Release with the generated installers.

## Windows code signing

Unsigned installers may cause SmartScreen warnings. The workflow includes an optional `signtool` step. To enable it, open **Settings → Secrets and variables → Actions → New repository secret** and add `WINDOWS_CERTIFICATE_BASE64` containing the Base64-encoded PFX certificate, plus `WINDOWS_CERTIFICATE_PASSWORD` containing its password. The signing step uses SHA-256 and a trusted timestamp server, and runs only when the certificate secret is present. A certificate, private key, password, and publisher identity are required; these cannot be generated by the source repository and must be supplied by the publisher. Never commit a PFX file or password to Git.

The application itself does not require a server or account. Windows installations should have the WebView2 runtime, which is present by default on current Windows 10 and Windows 11 installations.
